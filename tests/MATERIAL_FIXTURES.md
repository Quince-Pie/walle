# Independent material packet fixtures

`material_fixture_data.h` was generated from the retained macOS26.6.1 source
implementation: `lg_material.material_adapter.render_inputs`, `lg_host`, and
`lg_colormap`. No C implementation output was used to make expected bytes.
`material_fixture_provenance.json` records the source and generator hashes.

The32 cases are regular/clear × light/dark × four tints × two logical sizes and
backing scales. Tints are absent, opaque chromatic, present alpha0, and partial
alpha. Sizes include the source map's small48-point input and a1080-point input.
The declared context is active, fixed incoming appearance, source defaults, SDR.

`material_contracts.c` compares every active packet segment, the2048-byte tint
ramp, presence/kernel selection, and relevant planning scalars. Absent tint
buffers are not treated as a rendered tint layer. Expected ramps are deduplicated
only after the source generator confirms all present-tint cases produce the same
source-defined ramp. No sampled multidimensional recipe or color table is used.

Run `python tests/run_material.py` for the production
`-O3 -flto=auto -ffp-contract=off` profile. Add `--sanitize` for the separate
`-O1 -fsanitize=address,undefined` profile. Both run without a display, Vulkan,
or the original Python extraction. Results and hashes go to
`build/tests/material/`. `--root` and `--cc` support isolated candidate checks.

Initial verification: both profiles match32 cases,62784 bytes and776 scalar
values with zero mismatches; the sanitizer run is clean. These finite regression
fixtures support the source port without claiming exhaustive RGB or cross-GPU
numerical equivalence.

To regenerate independently, run `tools/generate_material_fixtures.py` with
`--host-source` pointing to the retained extraction's `liquidglass/host` and
`--output-dir` pointing to a separate directory. Compare generated bytes before
replacing accepted fixtures. Normal builds and checks need neither that workspace
nor Apple frameworks.
